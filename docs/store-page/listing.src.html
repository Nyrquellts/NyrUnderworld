Before you buy — will it work on your server

The honest compatibility answer

Read this part properly. It is the one thing that decides whether this is right for you, and getting it wrong is how people end up asking for refunds.

Fresh serverYes. The intended case. Drop it in, one ensure, and you have a city.
Existing ESXNo. It does not sit on ESX and does not read its players, jobs or money. It would be a second framework beside the first.
Existing QBCoreNo. Same answer, same reason. There is no bridge, and this page will not pretend there is one.
Existing QBOXNo. No bridge is included or verified.
Map / vehicle / clothing packsYes. Those are streamed assets and do not touch gameplay rules.
GTA V LegacyYes. Declared and booted. The full playtest runs against the Legacy server.
GTA V EnhancedYes. The manifest declares gta5enhanced and the Enhanced server starts it.
OneSyncRequired — and the manifest declares it, so the server enforces it rather than failing quietly.
txAdminYes. It is an ordinary resource in resources/.

Said plainly: NYR Underworld is what you run instead of ESX or QBCore, not something you bolt onto one.

That narrows who it is for, and it is the reason it can be what it is. It has no compatibility layer to work around, no other framework’s assumptions to honour, and no dependency that can break it on a Tuesday because somebody else pushed an update.

If you are starting a server, or rebuilding one, that is the whole argument. If you have two years of ESX data and players on it, this is not the purchase for you, and you should not make it.

Installation

Three lines, and no order of operations

Nothing has to start before it. No framework to configure first, no SQL file to import by hand, no shared object to wire up.

  1. Drop the folder into resources/. A FiveM resource is named by its folder, so the folder is nyr_underworld.

  2. Add ensure nyr_underworld to server.cfg. That is the entire configuration required to start.

  3. Start the server. The city builds itself from config.lua and tells you exactly what it made.

[nyr] the city is kept in files under
      nyr_underworld/data
[nyr] added from config.lua: 2 employers,
      4 addresses, 2 branches, 1 shops,
      2 blocks, 1 fences
[nyr] the city is at day 0 monday 08:00
      with 0 people, 6 addresses

Want it in MySQL instead? set nyr_store database. The table is created on first boot and it speaks to the oxmysql you already run. That is the whole migration.

Make it your city

You edit data, not code

Items, jobs, addresses, banks, shops and their prices, the blocks a crew can hold, who buys stolen goods. All of it is one file — and the whole file is checked before anything is built.

-- config.lua
shops = {
    {
        name = "Rob's Liquor",
        at   = "Rob's Liquor, Grove Street",
        prices = {
            water   = { buy = 250,  sell = 100 },
            bandage = { buy = 1200, sell = 400 },
            scrap   = { sell = 900 },  -- taken in, never sold
        },
        restock = { water = 60 },
        float = 50000,
    },
},

Money is whole cents everywhere: 250 is $2.50. There is not one decimal in the file, because a decimal in a price is the mistake that quietly costs you money.

Four typos, six problems, one restart. A misspelled key is refused rather than ignored — the worst config failure is the one where everything looks right and the setting silently does nothing.

Adding to the config adds to the city. Entries match by name, so a shop added and a server restarted is a new shop, and everything already there keeps its stock, its till and its owner. Restarting never reverts a city to its seed.

Persistence

It will not lose your players’ work

Out of the boxJSON inside the resource. No database, no dependency, no setup. A corrupt file falls back to its backup and says so in the console.
One line laterset nyr_store database — MySQL through the oxmysql you already run. One table, created on first boot. One thing to back up.
SpeedEach collection is read once at boot and served from memory after, so a player’s request never waits on the database. Only rows that changed are written, batched 200 to a statement.
If it cannot be readIt refuses; it does not forget. Corrupt files with an unreadable backup, or a database that has gone away: every request touching that collection is refused until it can be read again, and nothing is written over it. Same rule in both stores.
If MySQL is missingIt will not start, and names what it looked for. It never quietly falls back to files.
Saving through itA refusal is reported every save tick, in the console, for as long as it lasts. It never takes the save loop down — a city running with nothing writing it down is the one outcome worse than a refusal.

Why that rule is the whole point. If unreadable looked like empty — a dead database, or a corrupt file whose backup is also gone — the character system would find nobody, make a fresh character over the top of somebody’s, and the next save would write it down over the last good copy.

A refused command is recoverable. A city overwritten with a blank one is not. The failure mode is chosen, deliberately, to be the annoying one rather than the unrecoverable one.

The same instinct runs through the money: every movement is a double-entry posting and the total is always zero. Money cannot be created or destroyed by accident, only moved — and one console command tells you whether that is still true.

Admin and creator tooling, included

Twelve console commands, three staff ranks, an audit trail, and a live read of the running city that does not mean reading a log file.

nyr summary     the state of the city
nyr verify      are the books still balanced
nyr audit       what was asked, what came back
nyr errors      everything that went wrong

            whether it is keeping up

nyr commission  make somebody police
nyr found       found a crew
nyr wanted      who has heat, ranked
nyr turf        who holds which block
  • nyr verify is the one that matters. It checks that the ledger totals to zero, that every asset has exactly one owner, that the inventory has duplicated nothing, and that the record is intact. One command tells you whether your economy is still whole.
  • Admin power is granted from the console, never claimed. Three ranks, and capped: one command cannot create more than a set amount of money or spawn more than a set number of items, whoever runs it.
  • Every admin action is in the audit trail under the name that did it, so “who gave themselves a car” has an answer.
  • A LAN dev bridge — /state, /log and /do over HTTP — lets you read and drive the running city while you build it. Gated on sv_lan: a public server installs none of it.

Built to be run by one person. The tools that keep a city honest ship in the same folder as the city.

The mechanic it is named after

A crime nobody saw leaves a full record and no heat

The city keeps two things, deliberately apart. The record is what happened: written whether or not anybody saw it, never edited, never expiring. A burglary with no witnesses still leaves a record, and that record is what lets a detective find it later — instead of needing an eyewitness who no longer plays on your server.

Standing is what the city currently thinks. It moves when things happen and drifts back toward nothing when they stop. Heat cools.

The interesting part falls out of keeping them apart. Commit a crime with no witnesses and you generate no heat and a complete record. Nobody is looking for you. The evidence is sitting there with your name on it.

Wait out the heat and you are no longer hunted, and still the person who did it. Somebody can find that out in a month and act on it.

Which records move which standing is a table, so a new kind of crime is a line of configuration — not a new code path in three systems.

What you are not buying

The gaps, said here rather than found later

If one of these is a dealbreaker, better that you know before you pay. Nothing on this page is worth a refund request.

  • No emergency services. Health has downing, bleeding out and revival. The EMS role, dispatch and a hospital as a place are not built.
  • No licences or courts. A sentence is a fine.
  • No streamed assets. No custom vehicles, clothing, MLOs or maps. This is rules and screens; the map is Los Santos as it ships.
  • No drag-and-drop inventory. The grid is click, count, act.
  • No HUD overlay. me.status answers with everything a HUD needs; drawing one over the game is not included.
  • Not load-tested with hundreds of live players. The persistence is built for it and has not been proved at that scale. That claim is not made.
